# Google Play: проверка готовности LectureVault

Дата проверки: 10 сентября 2026. Повторная проверка выполнена после обновления интерфейса 1.1.0. Отчёт не подтверждает прохождение модерации Google Play.

## Повторная проверка версии 1.1.0

- Android имеет `versionCode = 2`, `versionName = 1.1.0`, `targetSdk = 36`.
- Облачная цепочка больше не требует заранее скачанную Vosk-модель: сначала запускаются Groq и Gemini, затем при ошибке облака используется установленная локальная модель.
- Перед отправкой аудио и текста требуется явное согласие. В настройках появились объяснение обработки и удаление API-ключей.
- `assembleDebug`, `bundleRelease`, debug/release unit tests и `lintRelease` завершились успешно. Полученный AAB намеренно не подписан, потому что upload key издателя не предоставлен.
- Новый APK проверен только сборкой; подключённого Android-устройства и готового system image на этой машине нет, поэтому финальный ручной прогон Android UI остаётся обязательным.

## Подтверждено локально

- `app/build.gradle.kts`: `compileSdk = 36`, `targetSdk = 36`, `minSdk = 26`, `versionCode = 2`. Используется Android Gradle Plugin 8.13.1.
- Manifest запрашивает микрофон, интернет, уведомления и foreground-service разрешения. Записывающий сервис имеет тип `microphone`, сервис WorkManager — `dataSync`. Нет разрешений на контакты, геолокацию, SMS и широкого доступа ко всем файлам. Папка Obsidian выбирается через системный SAF.
- HTTP без TLS запрещён. Резервное копирование приложения отключено. Android API-ключи сохраняются в зашифрованном виде через Android Keystore.
- Android-облако работает по цепочке: аудиофайлы → Groq → текст → Gemini → Markdown в выбранной папке. Свой сервер и пользовательские аккаунты не обнаружены.

## 16 KB: статическая проверка пройдена

В проверенном debug APK с SHA-256 `4631E774AF4182F51A627A84E8BDAF13EB2C3FADDA1E42187C5BEA4FBE9D6310` используется Vosk 0.3.75.

- `lib/arm64-v8a/libvosk.so` и `lib/x86_64/libvosk.so`: все ELF `LOAD` сегменты имеют выравнивание 16384 (`2**14`). Проверено NDK 28.2 `llvm-objdump -p`.
- 64-битные `libjnidispatch.so` также имеют выравнивание 16384; проверено чтением ELF-заголовков.
- `zipalign -c -P 16 -v 4 app-debug.apk`: `Verification successful`.
- 32-битные варианты Vosk имеют выравнивание 4096; проверяемое требование Google Play относится к 64-битным устройствам.

Это не заменяет запуск релизной сборки на устройстве/эмуляторе с 16 KB страницами. После итогового `bundleRelease` необходимо проверить APK, созданные из релизного AAB, и выполнить такой запуск. [Официальная инструкция проверки 16 KB](https://developer.android.com/guide/practices/page-sizes).

Текущая инструкция Android указывает 1 февраля 2027 для блокировки обновлений без поддержки 16 KB. Старые официальные статьи называли 1 ноября 2025; актуальные ограничения конкретного приложения следует проверять в Play Console.

## Что пока не позволяет назвать проект готовым к публикации

1. **Нет подтверждённого подписанного релизного AAB.** В Gradle отсутствует release signing configuration. Выданный ранее APK подписан `CN=Android Debug`, что проверено `apksigner verify --print-certs`. Найденный `app-release-unsigned.apk` старше текущего кода и не является релизом этого обновления. Новым приложениям требуются Android App Bundle, upload key и Play App Signing. Ключи публикации при аудите не создавались. [Подпись приложения](https://developer.android.com/studio/publish/app-signing), [Загрузка в Play Console](https://developer.android.com/studio/publish/upload-bundle).

2. **Политика конфиденциальности не закончена для магазина.** Исходный `PRIVACY.md` описывает передачу в Groq/Gemini, но обещает отсутствовавшую в интерфейсе кнопку удаления ключей. В исходном Android UI нет ссылки или текста политики. Нет подтверждённого публичного URL политики и контакта издателя. Google требует доступную внутри приложения политику и публичный URL в Play Console, с описанием обработки, хранения, удаления и контактами. [Политика User Data](https://support.google.com/googleplay/android-developer/answer/10144311?hl=en).

3. **Не заполнены сведения магазина.** Data safety должна учитывать отправку аудио и текста сторонним API: отсутствие собственного сервера не означает отсутствие передачи данных с устройства. Требуется определить категории аудиозаписей/документов/пользовательского текста и проверить условия обработчиков перед декларацией. [Как заполнять Data safety](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en).

4. **Не проверен статус аккаунта издателя.** Для личных аккаунтов, созданных после 13 ноября 2023, перед заявкой на production access требуется закрытое тестирование с минимум 12 участниками, непрерывно подключёнными 14 дней. Неизвестно, относится ли это к аккаунту пользователя. [Требования к тестированию](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en).

Требование target API уже выполнено: с 31 августа 2026 новые приложения и обновления обычных Android-приложений должны целиться в API 36 или выше. [Текущие требования target API](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en).

## Исправленные сценарии базового интерфейса

- Требование локальной модели для облачного режима устранено.
- `AppSettings.consent` теперь реально управляет отправкой данных, а не просто хранится без использования.
- Сохранённые ключи показываются как `Groq ✓ Gemini ✓` без проверки. Кнопка «Проверить API» проверяет доступ к сведениям моделей, а не реальную транскрипцию/генерацию и не остаток квоты.
- Основной статус показывает «ГОТОВО» при обработке. Очередь подписана «Ожидает интернета», хотя локальной обработке интернет не требуется.
- Готовые импортируемые записи принимаются до 1 GB, но Groq-клиент отклоняет файл больше 24 MiB и часть форматов. Базовый worker молча переключается на локальную обработку. При облачном режиме без модели нужен понятный результат ошибки, а не обещание успешной обработки.
- `SecretStore.clear()` реализован, но кнопки вызова в базовых настройках нет. Удаление приложения очищает его приватные записи; экспортированные заметки Obsidian остаются.

## Проверка перед отправкой

После изменения сценариев проверить первый запуск, отказ в разрешении микрофона, запись с заблокированным экраном и остановку из уведомления, импорт большого файла, отсутствие сети, исчерпанную облачную квоту, локальную обработку, отзыв доступа к vault и чтение созданной заметки в Obsidian. Проверки Android API endpoints не заменяют один полный прогон «аудио → расшифровка → конспект → файл».
